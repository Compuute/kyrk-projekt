# CLAUDE.md — Claude Code Guidelines for kyrk-projekt

Welcome! When running under **Claude Code**, please follow these commands and guidelines strictly to comply with the project's quality and security guards.

---

## 1. Quick Commands

* **Install Dependencies**: `make install` (installs all Python service requirements in the virtual environment + frontend npm deps via `npm ci`)
* **Run Repo Guard Tests**: `.venv/bin/pytest tests/`
* **Run All Tests**: `make test` (Python, Node, PWA, Eleventy, and Guardrails)
* **Run One Service Tests**: `make test-<service-name>` (e.g., `make test-membership-service`)
* **Lint Code**: `make lint` (syntax check + Terraform format check)
* **Validate Terraform**: `make tf-validate`
* **Local Run Zitadel**: `./scripts/start-local-zitadel.sh`

---

## 2. Core Development Rules (AI-RULES.md)

Always read [AI-RULES.md](AI-RULES.md) for full context.

1. **Hexagonal Architecture (Ports & Adapters)**:
   - Routes (`app/api/`), Ports (`app/ports/`), and Domain Orchestrators (`app/services/`) **must NEVER** import vendor SDKs (like `google.cloud`, `httpx`, `anthropic`, `requests`).
   - Vendor integrations are strictly restricted to the `app/adapters/` directory.
2. **Test-Driven Development (TDD)**:
   - Always write tests first, then write the code to make them pass.
   - Maintain at least **60% coverage**. Never modify tests to fit broken code.
3. **Zero-Trust PII Zonemodel**:
   - RED Zone: Raw PII data (personnummer, names, emails, phones) must never leak to logs, external webhooks, or LLM APIs.
4. **Committer Hygiene (RULE 4)**:
   - NEVER add comments like `"generated by"`, `"written by AI"`, or add session-IDs in source code, commit messages, or documentation. A local hook + CI gate (`commit-hygiene`) enforce this — set your git identity with `git config user.name` / `user.email`.

## 3. Ops Agent & SRE Rules

Always read [ops-contract.yaml](ops/ops-contract.yaml) and [well-architected-guidelines.md](docs/governance/well-architected-guidelines.md) before SRE operations.

1. **Ops CLI**: Never run raw `gcloud`, `gsutil`, or `terraform` commands directly. Use the [ops-cli.py](ops/ops-cli.py) tool:
   - `python ops/ops-cli.py health`
   - `python ops/ops-cli.py logs <service>` (automatically filters out PII)
   - `python ops/ops-cli.py status`
   - `python ops/ops-cli.py backup verify`
   - `python ops/ops-cli.py drift check`
   - `python ops/ops-cli.py incident create "<title>"`
2. **Forbidden Actions**: Do not delete Firestore data, alter IAM policies, force push to main, or deploy to production without manual approvals.

## 4. Modellpolicy (AI-sessioner)

Repo-default är **Sonnet** (satt i `.claude/settings.json`) — rätt för
välspecificerad implementation, vilket är majoriteten av arbetet. Tre
subagenter med låsta modeller finns i `.claude/agents/` och väljs
automatiskt vid delegering: `utforskare` (Haiku — kodsökning),
`implementerare` (Sonnet — exekvering mot spec), `granskare` (Opus —
PII-/korrekthetsgranskning före merge).

**Eskalera manuellt till Fable/Opus** (`/model`) när uppgiften är öppen
eller felkostnaden hög: arkitekturbeslut, säkerhets-/PII-design,
felsökning som spänner över flera system. Prisrelationer att väga mot:
Fable ≈ 2× Opus ≈ 3× Sonnet ≈ 10× Haiku.

Arbetsregler som håller nere tokenkostnaden oavsett modell:
- **En session = en issue = en branch.** Kolla `gh issue list` innan du
  börjar — pågår arbetet redan någonstans är svaret där, inte i en ny
  utredning.
- **Skriv ner dyra svar.** Kostade en fråga en lång utredning ska svaret
  in i `docs/`, en issue-kommentar eller denna fil innan sessionen stängs.
- **Starta sessioner i repo-roten** (inte hemkatalogen) så att denna fil,
  settings och git-kontexten laddas automatiskt.
- Modellval i **produktkod** hårdkodas aldrig i anropet — modell-id per
  användningsfall ligger i konfig/env så att byten är en konfigändring.
